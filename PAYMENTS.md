# Приём платежей

Подтверждение оплаты вынесено за один интерфейс, чтобы смена платёжного
провайдера была правкой в `.env`, а не переписыванием бота.

## Как это работает

Логика сверки не зависит от источника денег и не менялась:

1. При создании заказа генерируется уникальный комментарий `ARA-XXXXXXXX`
   (`payment_comment`) и точная сумма к оплате (`payable_amount`).
2. Клиент платит, указав этот комментарий.
3. Провайдер отдаёт список входящих операций.
4. `operation_matches_payment()` сводит операцию с заказом по трём условиям:
   сумма совпадает до копейки, комментарий содержит токен, время операции не
   раньше создания заказа минус 2 минуты.
5. `settle_operations()` подтверждает заказ.

Меняется только шаг 3. Все провайдеры отдают операции в одном виде:

```python
{
    "id":            "tx-1",                  # идентификатор операции
    "time":          "2026-11-12T10:30:00Z",  # ISO 8601, UTC
    "comment":       "Перевод СБП ARA-AB12CD34",
    "purpose":       "Перевод СБП ARA-AB12CD34",
    "accountAmount": {"cents": 123456},       # копейки
}
```

Подтверждение **идемпотентно по `id` операции**: повторная доставка того же
колбэка ничего не зачислит дважды.

## Провайдеры

| `PAYMENT_PROVIDER` | Режим | Что делает |
|---|---|---|
| `manual` | manual | Автоматической сверки нет, админ подтверждает в боте |
| `ozon` | pull | Старый скрапер Озон-банка, опрос раз в `OZON_CHECK_INTERVAL_SECONDS` |
| `webhook` | push | Колбэк банка или агрегатора на `POST /payments/webhook` |

Синонимы `webhook`: `bank`, `bank_webhook`, `aggregator`.

Если `PAYMENT_PROVIDER` не задан, значение выводится из остальной конфигурации:
`ozon`, когда заданы `OZON_COOKIES_JSON` или `OZON_USE_SELENIUM`, иначе
`manual`. Поэтому добавление этого слоя ничего не меняет на уже работающем
сервере.

При нераспознанном значении или при `webhook` без секрета провайдер
откатывается в `manual` с записью в лог — но никогда в неподписанный приём.

## Текущий провайдер

```
curl -s http://127.0.0.1:8000/payments/health
```

Поле `mode` всегда одно из `pull` / `push` / `manual`.

## Настройка вебхука

```ini
PAYMENT_PROVIDER=webhook
PAYMENT_WEBHOOK_SECRET=<ключ подписи от банка>
PAYMENT_WEBHOOK_SIGNATURE_HEADER=X-Signature
PAYMENT_WEBHOOK_SIGNATURE_ALGO=sha256
PAYMENT_WEBHOOK_LABEL=tochka
```

Эндпоинт: `POST /payments/webhook`. Он отдаёт

* `401` — подписи нет или она не сходится;
* `400` — тело не JSON;
* `200` — доставка прочитана (в том числе когда зачислять нечего: списание,
  комиссия, посторонннее событие). 200 нужен, чтобы банк перестал
  ретраить.

### Подпись

HMAC от **точного тела запроса**, сравнение в постоянном времени. Принимается
hex или base64, с префиксом вида `sha256=` или без. Алгоритм — любой из
`hashlib`.

Без секрета и без заголовка подписи проверка не проходит: эндпоинт платежей
без подписи — это способ оформлять заказы бесплатно.

### Доступ извне

Бэкенд слушает `127.0.0.1:8000`, поэтому колбэк банка до него не дойдёт.
Нужен реверс-прокси с TLS, открывающий **только** путь вебхука — остальной API
админский и наружу не выставляется:

```nginx
server {
    listen 443 ssl;
    server_name pay.example.com;

    ssl_certificate     /etc/letsencrypt/live/pay.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/pay.example.com/privkey.pem;

    # Наружу — только вебхук.
    location = /payments/webhook {
        proxy_pass http://127.0.0.1:8000/payments/webhook;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / { return 404; }
}
```

Банку отдаётся `https://pay.example.com/payments/webhook`. Если провайдер
публикует диапазоны своих адресов, ограничьте ещё и по IP (`allow` / `deny`),
но подпись остаётся обязательной: фильтр по адресу её не заменяет.

Самоподписанный сертификат не подойдёт — банк проверяет цепочку.

### Разметка полей

У каждого банка своя структура тела, поэтому расположение полей — это
конфигурация, а не код. Путь задаётся через точку: `Data.Transaction.0.amount`.

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `PAYMENT_WEBHOOK_EVENTS_PATH` | — | Путь к списку операций, если тело их оборачивает |
| `PAYMENT_WEBHOOK_FIELD_ID` | `id` | Идентификатор операции |
| `PAYMENT_WEBHOOK_FIELD_AMOUNT` | `amount` | Сумма зачисления |
| `PAYMENT_WEBHOOK_FIELD_COMMENT` | `purpose` | Назначение платежа с токеном |
| `PAYMENT_WEBHOOK_FIELD_TIME` | `time` | Время операции |
| `PAYMENT_WEBHOOK_AMOUNT_UNIT` | `rub` | `rub` или `cents` |

Суммы принимаются как `1234.56`, `"1234,56"`, `"1 234.56"`. Время — ISO 8601
с зоной или без, `12.11.2026 13:30:00`, Unix-таймстамп в секундах или
миллисекундах. Операции с неположительной суммой отбрасываются.

### Пример: вложенный массив

```ini
PAYMENT_WEBHOOK_EVENTS_PATH=Data.Transaction
PAYMENT_WEBHOOK_FIELD_ID=transactionId
PAYMENT_WEBHOOK_FIELD_AMOUNT=Amount.amount
PAYMENT_WEBHOOK_FIELD_COMMENT=description
PAYMENT_WEBHOOK_FIELD_TIME=bookingTimestamp
```

Подходит для тела вида:

```json
{"Data": {"Transaction": [
  {"transactionId": "t1",
   "Amount": {"amount": "500.00"},
   "description": "Перевод СБП ARA-AB12CD34",
   "bookingTimestamp": "2026-11-12T10:30:00+03:00"}
]}}
```

### Пример: плоское тело

```ini
PAYMENT_WEBHOOK_FIELD_ID=operation_id
PAYMENT_WEBHOOK_FIELD_AMOUNT=sum
PAYMENT_WEBHOOK_FIELD_COMMENT=comment
PAYMENT_WEBHOOK_FIELD_TIME=created_at
PAYMENT_WEBHOOK_AMOUNT_UNIT=cents
```

## Что запросить у провайдера

Прежде чем настраивать, попросите письменно:

1. **Какой банк-эквайер обслуживает платежи** и номер его лицензии.
   Настоящий агрегатор отвечает сразу; приём платежей в РФ ведёт только
   лицензированная кредитная организация.
2. Спецификацию вебхука: события, формат тела, схему подписи, политику
   повторных доставок.
3. Тарифы, сроки выплат, условия холда и резерва — в договоре, не на словах.
4. Юрлицо, ИНН, ОГРН.

## Тесты

```
./tests/run_all.sh                  # венв бэкенда или python3
./tests/run_all.sh /path/to/python  # конкретный интерпретатор
```

* `test_providers.py` — разметка полей, суммы, время, проверка подписи
* `test_webhook_e2e.py` — заказ подтверждается подписанным колбэком; отклонение
  неподписанных, подделанных, несовпадающих по сумме и комментарию; повтор не
  зачисляет дважды
* `test_default_regression.py` — на конфигурации без `PAYMENT_PROVIDER`
  поведение не меняется

Тестам нужны `fastapi`, `pydantic`, `httpx`, `python-dotenv`, `aiohttp`,
`requests`, `tonsdk`. Selenium не требуется.

## Про Озон

Провайдер `ozon` оставлен для преемственности. Он держит живую авторизованную
сессию банка и ломается при каждом обновлении антибот-защиты. На сервере при
этом лежат куки сессии и PIN в открытом виде, так что скрапер стоит выключить,
как только появится вебхук.
