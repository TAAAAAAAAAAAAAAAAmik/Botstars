# Сайт и правовые документы AraStars

Комплект для подачи заявки в платёжный сервис: витрина с тарифами и четыре документа,
которые обычно проверяют при верификации — оферта, пользовательское соглашение,
политика обработки персональных данных и порядок возврата.

## Что внутри

| Файл | Назначение |
|---|---|
| `index.html` | Главная: описание услуги, тарифы, порядок оказания, контакты и реквизиты |
| `offer.html` | Публичная оферта — договор с заказчиком по ст. 437 ГК РФ |
| `terms.html` | Пользовательское соглашение: правила бота, баланс, рефералка, блокировки |
| `privacy.html` | Политика обработки персональных данных по 152-ФЗ |
| `refund.html` | Порядок и сроки возврата средств |
| `assets/style.css` | Оформление, светлая и тёмная темы |
| `build.sh` | Подставляет ваши данные в шаблоны и собирает сайт в `docs/` |
| `config.env.example` | Шаблон с полями для заполнения |

Шаблоны содержат плейсхолдеры вида `{{SELLER_NAME}}`. Руками их править не нужно —
этим занимается `build.sh`.

## Как собрать

```bash
cd site
cp config.env.example config.env
nano config.env          # заполнить ФИО, ИНН, почту, адрес сайта и ссылку на бота
./build.sh
```

Готовый сайт появится в `docs/` в корне репозитория. Скрипт проверит, что все поля
заполнены, и откажется собирать, если что-то осталось пустым.

Посмотреть локально:

```bash
cd docs && python3 -m http.server 8080
```

`config.env` в git не попадает — он в `.gitignore`.

## Как опубликовать через GitHub Pages

Root на сервере не нужен, хостинг бесплатный.

```bash
git add docs
git commit -m "Добавить сайт с офертой"
git push
```

Затем в репозитории: **Settings → Pages → Source: Deploy from a branch →
Branch: `main`, папка `/docs` → Save**. Через минуту сайт будет доступен по адресу
`https://<ваш-логин>.github.io/Botstars/`.

Этот адрес и указывайте в заявке в платёжный сервис.

Две оговорки:

- Для **приватного** репозитория GitHub Pages требует платный тариф. Если репозиторий
  приватный — создайте отдельный публичный репозиторий только под сайт и положите
  содержимое `docs/` в его корень.
- Если позже появится свой домен, его можно привязать там же, в настройках Pages.

## Как разместить на своём сервере

Понадобится root для nginx. Пример конфигурации:

```nginx
server {
    listen 80;
    server_name arastars.example.com;
    root /home/tamik/botstars/docs;
    index index.html;
}
```

Сертификат — `certbot --nginx -d arastars.example.com`.

## Обновление документов

Правьте шаблоны в `site/`, затем пересоберите:

```bash
cd site && ./build.sh && cd .. && git add docs && git commit -m "Обновить документы" && git push
```

При изменении условий не забудьте поменять `DOC_DATE` в `config.env` — дата редакции
проставляется во все документы.

## Важно

Тексты составлены по типовой структуре и покрывают то, что обычно проверяют платёжные
сервисы. Это не заменяет юридическую проверку: перед реальным оборотом документы стоит
показать юристу, особенно разделы об ответственности и возвратах.

Отдельно проверьте, что описание услуги в оферте совпадает с тем, что вы указали
в заявке платёжному сервису — расхождение между заявленной и фактической деятельностью
приводит к блокировке аккаунта.
